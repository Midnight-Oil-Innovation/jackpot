Meet JACKPOT

What happens from the moment a swab is collected to the moment a public health alert goes out — and the software that makes it possible.

JACKPOT stands for Joint ASU/ADHS Center for Pathogen Genomics and One-Health Tracking. It's a platform built at Arizona State University in partnership with the Arizona Department of Health Services to track infectious disease outbreaks using genomic sequencing.
🦠

What it tracks

Viruses, bacteria, and other pathogens — from COVID-19 and flu to Salmonella and Valley fever

🧬

How it works

By reading the genome of each pathogen, it can tell whether two cases are related or coincidental

🏥

Who uses it

Public health officials, academic researchers, and epidemiologists tracking disease spread across Arizona and beyond

Why Sequence the Genome at All?

Traditional lab tests tell you what pathogen is present. Genomic sequencing tells you which exact version — and that difference is huge for outbreak detection.

The postal code analogy: Knowing someone has COVID is like knowing they live in "Arizona." Knowing their lineage is like knowing their exact street address. It lets you trace who infected whom.
1

Cluster Detection

When two patients have genomes that differ by only 1–2 mutations, they likely share a transmission chain. JACKPOT makes this comparison automatic.

2

Variant Tracking

Which new variants are circulating in Arizona? When did they arrive? Is this a local spread or travel-imported? The genome answers all of these.

3

National Reporting

JACKPOT formats genomic data for NCBI, GISAID, and CDC — so Arizona data feeds into the global picture.

The Schema Blueprint

Every sample stored in JACKPOT must follow a strict set of rules. This module is about those rules — what they are, why they exist, and how they're written.

The passport analogy: A passport is a schema. It has required fields (name, birthdate, nationality), optional fields (middle name), and controlled values (country codes). If you leave a required field blank, the passport is invalid. JACKPOT's schema works the same way for pathogen data.
✅

Required fields

Fields every sample must have — like sample_id, organism_name, date_collected

📋

Controlled vocabularies

Fields that only accept specific values — like sequencing_platform (Illumina, Nanopore, etc.)

🔗

Linked standards

Each field maps to a global standard — NCBI BioSample, WHO, CDC — so data can be shared automatically

Inheritance in Action

Here's exactly how a subclass is defined in the real schema file. HumanSample says is_a: Sample — meaning it gets all of Sample's ~60 fields for free, then adds its own.

CODE 

HumanSample:
  is_a: Sample
  description: >
    Clinical or surveillance sample
    from a human host.
  attributes:
    adhs_medsis_id:
      required: true
    host_age:
      range: integer
    clinical_outcome:
      description: >
        e.g. hospitalized, ICU, deceased
PLAIN ENGLISH

HumanSample: — here is the name of this class, like a new tab in a form

is_a: Sample — this inherits everything from the base Sample class. All 60+ base fields come along automatically.

description: — a human-readable note about what this class is for

attributes: — the extra fields that ONLY HumanSample has

adhs_medsis_id — required: true means this field MUST be filled in. It links to the Arizona disease reporting system.

host_age: range: integer — age must be a whole number, not text like "forty"

clinical_outcome — how the patient fared: hospitalized, ICU, outpatient, etc.

Why Every Field Has a Global Address

Notice this in the schema: slot_uri: ncbi:host_age. That's an ontology URI. It means JACKPOT's host_age field is the same thing as NCBI's host_age field — universally.

The shipping container analogy: Before standardized shipping containers, every port had different equipment. Now one container fits any ship, truck, or crane worldwide. Ontology URIs are shipping container standards for data — a field with genepio:0001181 is recognized by any FAIR-compatible system anywhere on Earth.
🔗

NCBI BioSample

ncbi:host_age, ncbi:organism — the US government genomics database standard

🌐

GenEpiO / MIxS

genepio:0001181 — the epidemiology ontology used by WHO, GISAID, and PHA4GE

🏥

SNOMED / LOINC

Clinical coding systems — so JACKPOT data can link to electronic health records

Aha! FAIR data principles require that fields have stable global identifiers. Without ontology anchoring, data from different institutions can never be automatically combined — you'd have to manually map "collection_date" to "date_collected" to "col_dt" by hand.

03

One Health

70% of emerging infectious diseases come from animals. JACKPOT doesn't just track human cases — it tracks the whole ecosystem.

The watershed analogy: A river's health depends on everything upstream — soil runoff, wildlife, farms. You can't understand a river by only measuring it at one point. One Health treats human, animal, and environmental disease surveillance as a single interconnected system, not three separate problems.
👤

Human Sector

Clinical samples from patients — the traditional disease surveillance system

🦅

Animal Sector

Wildlife, companion animals, livestock, and vectors like mosquitoes and ticks

🌊

Environmental Sector

Wastewater, water, air, soil, food — pathogens leave traces before anyone gets sick

Human Samples: The Clinical Record

A HumanSample is the most data-rich sample type. It inherits all base fields, then adds everything epidemiologists need to understand the patient behind the pathogen.

CODE 

adhs_medsis_id:
  required: true

host_age:
  range: integer

host_age_range:
  range: AgeRangeEnum
  description: >-
    Decade bracket for privacy-preserving
    public surveillance reporting.

date_of_symptom_onset:
  range: date

travel_history_country:
  multivalued: true
PLAIN ENGLISH

adhs_medsis_id — required link to Arizona's disease reporting system. Every human sample must have one (or an exemption code). This connects the genome to the public health case record.

host_age: integer — the patient's exact age, stored internally for research analysis

host_age_range: AgeRangeEnum — the same age as a decade bracket (e.g. "25-34 years"). This version is shared publicly to protect privacy — exact age is considered PII.

date_of_symptom_onset — when symptoms started. The gap between this and collection date tells epidemiologists how fast the disease progresses.

travel_history_country: multivalued: true — countries visited in the 14 days before illness. Multiple countries are allowed (a list). Crucial for distinguishing local outbreaks from imported cases.

Animal Samples: Four Distinct Subclasses

JACKPOT has four specialized animal sample types, each with fields tuned to their surveillance context. The schema encodes real epidemiological knowledge about what matters for each species type.

🦎

WildlifeSample

Wild animals — bats, birds, deer, coyotes. Has travel_origin_region for migratory species (equivalent to travel history for humans). Critical for HPAI H5N1 tracking via flyways.

🐕

CompanionAnimalSample

Pets — dogs, cats. Has symptomatic (was the animal sick?) and vaccine_status_against_pathogen. Pets are the bridge species between wildlife and humans in many spillover events.

🐄

LivestockSample

Farm animals — poultry, pigs, cattle. Has antibiotic_use (tracking AMR sources) and distribution_scale (local vs. national supply chain).

🦟

VectorSample

Disease-carrying arthropods — mosquitoes, ticks. Has vector_species and vector_host_species (what animal was the vector feeding on?). Essential for West Nile, Zika, Rocky Mountain spotted fever.

Wastewater: The Early Warning System

Before a single person reports symptoms, the pathogen is already in the sewage. Wastewater surveillance is the most powerful early-warning tool in modern public health — it can detect an outbreak 4–7 days before clinical cases appear.

The smoke detector analogy: Clinical surveillance is like smelling smoke after the fire has started. Wastewater surveillance is like a smoke detector — it catches the signal before anyone's in danger.
CODE 

WastewaterSample:
  is_a: EnvironmentalSample
  attributes:
    wwtp_name:
      description: >
        Wastewater facility name.
        e.g. 'South Tempe Water
        Reclamation Facility'
    nwss_sewershed_id:
      description: >-
        CDC NWSS-assigned identifier
        for this sampling site.
    population_served:
      range: integer
PLAIN ENGLISH

WastewaterSample is_a: EnvironmentalSample — inherits from the environmental base class (which itself inherits from Sample). Two levels of inheritance.

wwtp_name — which treatment facility the sample came from. This is the physical location anchor for the data.

nwss_sewershed_id — the CDC's NWSS assigns a unique ID to every wastewater monitoring site in the US. By storing this ID, JACKPOT's Arizona data feeds directly into the national CDC surveillance database without manual matching.

population_served: integer — how many people's waste passes through this facility. Crucial for calculating prevalence rates (signal strength ÷ population = estimated infection rate).

Labs don't think in JSON. They think in Excel. JACKPOT bridges the gap — turning messy real-world spreadsheets into clean, standards-compliant genomic data.

The customs translator analogy: When goods cross a border, a customs broker translates the shipper's paperwork into the official format the government requires. The goods don't change — only the paperwork format. JACKPOT's mapping configs are customs brokers for genomic data.
1

Lab uploads a spreadsheet

Each lab has its own column names. "Sample ID" might be "Specimen No." at one lab and "ID" at another.

2

Mapping config translates it

A YAML config file says: "the column called 'Collection Date' maps to the schema field date_collected"

3

Required fields must be present. Controlled vocabularies must match. Dates must be in the right format.

4

What a Mapping Config Looks Like

Here's the actual mapping config for ASU's human sample spreadsheets. It's the bridge between a lab's custom column names and JACKPOT's standardized schema fields.

CODE 

source_format: asu_human_v1
target_class: HumanSample
column_mappings:
  "Sample ID": sample_id
  "Collection Date": date_collected
  "Pathogen": organism_name
  "Age": host_age
  "MEDSIS ID": adhs_medsis_id
file_detection:
  files_column: "FASTQ files"
  separator: ";"
  auto_detect_pairs: true
PLAIN ENGLISH

source_format: asu_human_v1 — this config applies specifically to ASU's human sample spreadsheet format (version 1)

target_class: HumanSample — incoming rows should be validated against the HumanSample schema class

column_mappings — the translation dictionary. The left side is the spreadsheet column header; the right side is the schema field name.

"Sample ID": sample_id — wherever the spreadsheet says "Sample ID", use that value for the schema's sample_id field

"MEDSIS ID": adhs_medsis_id — the lab calls it "MEDSIS ID", the schema calls it "adhs_medsis_id". The mapping bridges the gap.

file_detection: auto_detect_pairs: true — the FASTQ files are listed semicolon-separated in one column; auto-detect finds the paired R1+R2 files automatically.

The Three Quality Tiers

Not all data is equally complete. JACKPOT uses a tiered quality system so partial data can still be used immediately, while more complete data unlocks advanced features.

🌱

Tier 1: PRELIMINARY

Minimum viable data — enough to ingest and run pipelines. The sample is in the system immediately and available for analysis.

Required: sample_id, organism, date_collected, sequencing platform

📊

Tier 2: ANALYZABLE

Enough metadata for time-series charts and geographic maps. This is the tier public health dashboards require.

Also requires: collection location, host info, purpose for collection

🏆

Tier 3: SUBMITTABLE

Meets the full requirements of NCBI, GISAID, and CDC NWSS. The platform can automatically submit this sample to national databases.

Also requires: INSDC-compliant location names, VADR validation, complete lineage

Aha! Tiered quality is a practical solution to a real problem: labs want to upload data quickly, but regulatory databases demand perfection. By separating "ingestible" from "submittable," JACKPOT lets data flow in immediately while flagging what needs to be fixed for external reporting.

Submitting to the World: NCBI, GISAID, and CDC

When a sample reaches Tier 3 (SUBMITTABLE), JACKPOT can automatically format and submit it to national and international genomic databases. Each destination has different requirements — the schema is designed to satisfy all of them.

🏛️

NCBI BioSample / SRA / GenBank

The US National Library of Medicine. All published genomic research must deposit sequences here. JACKPOT uses TOSTADAS to submit. Sequences get permanent accession numbers (e.g., SAMN12345678).

🌍

GISAID

The global database for respiratory viruses — COVID, flu, RSV. Every SARS-CoV-2 variant name you heard during the pandemic (Alpha, Delta, Omicron) was named based on GISAID data. Arizona sequences become part of global variant tracking.

💧

CDC NWSS

The National Wastewater Surveillance System. Wastewater samples with a valid nwss_sewershed_id feed into the CDC's national wastewater dashboard — the one public health officials monitor nationally.

Why this matters for steering AI: When you ask an AI to "add a field that's required for NCBI submission," it needs to know which tier that is and what NCBI specifically requires. Knowing the SUBMITTABLE tier and NCBI BioSample standard helps you give precise instructions instead of vague ones.

Data Governance

Genomic data is powerful — and sensitive. JACKPOT has a layered system of access control, surveillance oversight, and schema versioning to keep data both useful and protected.

The archive room analogy: A research library has public reading rooms (anyone can access), restricted stacks (researchers with credentials), closed archives (special permission required), and a rare books vault (director approval only). JACKPOT's sharing levels work the same way — each level has different access rules.
🔒

Access Control

Five sharing levels from PRIVATE to PUBLIC, with a new REGISTERED_ACCESS tier for federated research networks

🏛️

Surveillance Oversight

ADHS has automatic visibility into reportable disease samples — but with a governance board override process

📜

Schema Evolution

The schema evolves through versioned Python scripts — changes are code, not manual edits, so they're reproducible and auditable

The Five Sharing Levels

Every sample in JACKPOT has a sharing_level that controls who can see it. Here are the five levels, from most to least restricted:

CODE 

SharingLevelEnum:
  permissible_values:
    PRIVATE:
      description: "Owner and Lab Director only"
    LAB:
      description: "All members of the owning Lab"
    DISCOVERABLE:
      description: "Metadata visible; files need request"
    REGISTERED_ACCESS:
      description: >-
        Available to any researcher who
        registers and accepts the DUA.
    PUBLIC:
      description: "Open to all authenticated users"
PLAIN ENGLISH

SharingLevelEnum — this is a controlled vocabulary (an enum) that lists all allowed values for the sharing_level field

PRIVATE — only the researcher who uploaded it and their Lab Director can see it. Default for sensitive or preliminary data.

LAB — visible to everyone in the same lab. Good for collaborative internal work.

DISCOVERABLE — other researchers can see the metadata (what pathogen, where, when) but must request access to the actual sequence files.

REGISTERED_ACCESS — any vetted researcher who signs the DUA gets instant access, no per-request approval needed. Added in v4.4 for GA4GH federated sharing.

PUBLIC — completely open to all authenticated platform users. Used for published, openly shared datasets.

The Surveillance Override System

JACKPOT automatically grants ADHS visibility into samples involving reportable pathogens. But labs can request overrides — with governance board review for privacy-sensitive changes.

I
Ingest Engine

Sample AZ-2026-0987 ingested. Organism: Salmonella enterica. Checking reportable organisms list...

I
Ingest Engine

Salmonella is a reportable pathogen in Arizona. Setting surveillance_relevant = TRUE automatically. ADHS will have oversight access.

L
Lab Director

This sample is from a federally-funded research study under a separate IRB. We need to request a surveillance override.

S
Governance Board System

Override request submitted. surveillance_relevant_override = TRUE, surveillance_override_pending = TRUE. Sample stays visible to ADHS until the board approves. Override category: research_exemption.

B
Governance Board Member

Override approved. IRB documentation verified. Setting surveillance_relevant = FALSE, surveillance_override_pending = FALSE. Audit logged.

I
Aha! Notice that surveillance_relevant stays TRUE until the board approves the override — never the reverse. This is a "fail-safe open" design: public health oversight is the default. Labs must justify removing it, not justify adding it.

How the Schema Evolves: Migrations as Code

Every version of the schema gets a dedicated Python script that applies changes. Here's how the v4.4 update script works — it's a great example of how software changes safely over time.

CODE 

# From update_schema_v4_4.py

CHANGES = [
  (
    "HumanSample — date_of_symptom_onset,
     travel history, age range",
    OLD_VACCINATION,
    NEW_VACCINATION,
  ),
  ...
]

def apply_changes(content):
  for description, old, new in CHANGES:
    if old not in content:
      raise ValueError("Anchor not found")
    content = content.replace(old, new)
PLAIN ENGLISH

CHANGES = [...] — a list of all the changes this script will make. Each entry has a description, the old text to find, and the new text to replace it with.

apply_changes(content) — a function that reads the current schema file and applies every change in the list.

if old not in content: raise ValueError — if the text to replace no longer exists, the script refuses to run and explains why. This prevents silent failures.

content.replace(old, new) — surgically replaces just the old section with the new one, leaving everything else intact.

Why this approach: By writing changes as code, every modification is version-controlled, can be run again on any machine, and has a clear record of what changed and why — unlike manually editing a YAML file.

What Changed in v4.4 and Why

Schema v4.4 was driven by WHO/CDC alignment requirements. Each addition solves a real surveillance gap:

1

date_of_symptom_onset

Standard on every WHO case investigation form but absent from most genomics platforms. The gap between symptom onset and sample collection reveals how fast a disease spreads.

2

travel_history_country

WHO situation reports always distinguish travel-linked from locally-acquired cases. Without this field, JACKPOT couldn't answer "did this outbreak start locally or arrive from abroad?"

3

OutbreakInvestigation class

Previously, "outbreak" was just a tag on individual samples. Now it's a first-class entity — you can query all samples belonging to a named outbreak, across all sectors, in one call.

4

REGISTERED_ACCESS sharing level

Required for CDC/WHO federated data sharing. Allows researchers at partner institutions to access data under a signed agreement without per-request approval — critical for international genomic surveillance networks.
