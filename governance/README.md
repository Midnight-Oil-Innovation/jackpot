# JACKPOT Governance

This directory contains the project's governance commitments. Each
document is intended to be a binding statement of how the project
operates, not aspirational text. Where commitments depend on mechanisms
that don't yet exist (e.g., the advisory board), the relevant document
is explicit about the trigger conditions and interim handling.

## Index

- [`charter.md`](charter.md) — Mission, scope, who the project is for, stewardship, funding posture.
- [`coi-policy.md`](coi-policy.md) — Conflict-of-interest disclosure expectations for maintainers and contributors.
- [`coi-disclosures.md`](coi-disclosures.md) — Current disclosures from individuals and entities with commit access.
- [`advisory-board.md`](advisory-board.md) — Forward-looking design for the advisory board, with trigger conditions for when it gets constituted.
- [`access-grievance-procedure.md`](access-grievance-procedure.md) — How grievances about JACKPOT software, governance, or CARE/sovereignty concerns are raised and handled.
- [`care-principles-and-tribal-data-sovereignty.md`](care-principles-and-tribal-data-sovereignty.md) — How the four CARE Principles map to specific JACKPOT architectural decisions and Scenario T defaults.
- [`benefits-sharing-framework.md`](benefits-sharing-framework.md) — Citation, collaboration, and data-back-to-source benefits, with per-scenario defaults.
- [`jurisdiction-and-data-residency.md`](jurisdiction-and-data-residency.md) — Where the project lives, where operator data lives, applicable law for operators.
- [`platform-shutdown-data-portability-plan.md`](platform-shutdown-data-portability-plan.md) — What happens to operators if Midnight-Oil-Innovation steps away from active maintenance.

## Status

These documents are currently in their initial complete form (Phase
24.5 deliverable, May 2026). Anticipated near-term updates:

- `coi-disclosures.md` populated with the current single-maintainer
  disclosures.
- Implementation-status tags added to `care-principles-and-tribal-data-sovereignty.md`
  for technical commitments that depend on Phase 24.5 design lockdown
  (sovereignty-compliant deletion) or P0c implementation (federation
  propagation).
- A `grievance-log.md` is created the first time a grievance is
  resolved through the procedure documented in
  `access-grievance-procedure.md`.
