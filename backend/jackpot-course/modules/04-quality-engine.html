The Quality Engine

The 3-tier validator, the file detective, and the privacy scrubber that protect every sample

Not All Data Is Created Equal

Think of JACKPOT's quality system like passport control at an airport. Every traveler gets through security (Tier 1). Only those with the right visas can board international flights (Tier 3). Getting through is not binary — it is a spectrum.

The key insight: missing fields do not block ingest. A sample with incomplete metadata is still stored — it just cannot be used for certain purposes. The validator tells you exactly what you need to add to unlock each tier.

🟢

Tier 1 — PRELIMINARY

The minimum to identify who, what, where, and when. sample_id, organism_name, source_type, date_collected, and 3 more required fields. Pipelines can launch immediately.

🟡

Tier 2 — ANALYZABLE

Adds epidemiological context: which lab sequenced it, the preparation method, the sequenced date. Required for epiweek calculations, time-series analysis, and external database indexing.

🔵

Tier 3 — SUBMITTABLE

Adds the fields GISAID and NCBI require: sequencing protocol, originating lab, submitting lab, county. Unlocks GISAID CSV export and NCBI BioSample/SRA submission.

🔬
A sample can be SUBMITTABLE but not ANALYZABLE

If a sample has all Tier 3 fields but only a year-precision date (YYYY, no month), it skips Tier 2 and jumps to Tier 3. NCBI and GISAID accept year-only dates; epiweeks require day and month precision. Both pathways are deliberately supported.

Inside the Validator

The validator checks metadata in a specific order — base fields first, then source-type-specific fields, then tier 2, then tier 3. Here is the structure from the real code:

CODE — backend/validator.py 

BASE_REQUIRED = [
    "sample_id",
    "organism_name",
    "source_type",
    "date_collected",
    "collection_location_country",
    "sequencing_platform",
    "type_of_experiment",
]

SOURCE_REQUIRED: dict[str, list] = {
    "Human": ["external_case_id", "biospecimen_type", ...],
    "Wastewater": ["population_served", "sample_type", ...],
    "Wildlife": ["host_species", "biospecimen_type", ...],
    "Isolate": [],  # no extra fields needed
}
PLAIN ENGLISH

BASE_REQUIRED: these 7 fields must be present on every sample, regardless of type. Missing any one = hard error, ingest rejected.

sample_id — the lab-assigned identifier for this sample

organism_name — which pathogen (e.g., “SARS-CoV-2”)

source_type — where was this collected: Human, Wastewater, Wildlife, etc.

date_collected — when the sample was taken from its source

...plus country, sequencing platform, and experiment type.

SOURCE_REQUIRED: each source type has additional required fields on top of the base 7.

Human samples require an external case identifier (external_case_id) and specimen type.

Wastewater requires flow rate, population served, and sampling method.

Wildlife requires the host species and specimen type.

Isolate has no extra requirements — it is the simplest source type.

The File Detective — Content Over Names

A sequencing file called sample.fastq is not automatically a FASTQ file. Someone might have renamed it by accident. JACKPOT's file_detector.py reads the actual bytes inside the file to confirm — and then pairs up R1 and R2 reads automatically.

isolate.fasta Assembly-only FASTA — no human reads, scrub_status = SKIPPED automatically
⚠️
FASTA files skip scrubbing automatically

If a sample has only FASTA files (no raw FASTQ reads), the human-read scrubbing step is automatically skipped — scrub_status = SKIPPED. FASTA files are assembled sequences with human reads already removed by the sequencer. Only the validator (not the router) is allowed to set this status.

The Validator Thinking Out Loud

A Human sample arrives. Here is the validation conversation — what the system checks and in what order.

⚡
Ingest Router

New sample from Lab 3. Source type: Human. Let me send it to the validator.

🔬
Validator

Checking the 7 base required fields... sample_id: present. organism_name: present. source_type: “Human” — valid. All 7 base fields: PASS. Moving on.

🔬
Validator

Source is Human. Checking Human-specific required fields... external_case_id: present. biospecimen_type: present. All Human-specific fields: PASS. Tier 1 achieved.

🔬
Validator

Checking Tier 2 fields... sequencing_lab: MISSING. date_sequenced: MISSING. Storing these in tier2_missing — ingest can still proceed at Tier 1.

🔬
Validator

Returning: valid=True, tier=1, tier2_missing=[“sequencing_lab”, “date_sequenced”]. Also auto-derived sector: “clinical” from source_type=Human.

⚡
Ingest Router

Sample accepted at PRELIMINARY. Writing to database with quality_status=PRELIMINARY and the tier2_missing list stored for the lab to see.
